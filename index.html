01 / SYSTEM

The network ends at the operator. The command continues as sound.

Apollo-26 separates transmission, validation, agent planning and execution. Each boundary receives typed data and checks what it owns.

  1. 01TX

    Ground station

    Signs a 34-byte frame and plays it as 300-baud Bell-202 audio from a phone or laptop.

  2. 02RX

    Acoustic daemon

    Demodulates sound, then checks sync, CRC, HMAC, replay and ranges before publishing a frame.

  3. 03MCP

    Kiro Flight Watch

    Waits for accepted frames, inspects the AGC, and requests the one canonical DSKY plan.

  4. 04AGC

    DSKY emulator

    Presses approved keys at a 100 ms cadence inside an AGC-faithful P00/P40 subset.

02 / SAFETY

The model proposes. The gate decides.

The agent can interpret a command, but it cannot invent the sequence, skip inspection, authorize a critical burn, or retry an uncertain actuation.

  1. 01

    Await

    Only daemon-accepted COMMAND and AUTH frames enter Flight Watch.

  2. 02

    Inspect

    Read one coherent AGC snapshot. KEY REL and OPR ERR must be clear.

  3. 03

    Plan

    Derive the only canonical key sequence from the signed command catalog.

  4. 04

    Authorize

    Critical P40 actions need one fresh operator AUTH bound to the COMMAND seq.

  5. 05

    Execute

    Recheck revision and keys, claim once, press at 100 ms cadence, verify postcondition.

Prompt-only agent

Apollo-26

  • Safety rules live only in a prompt.

    Rules execute in safety_gate.py and are checked independently inside the daemon.

  • The model chooses which keys to press.

    Execution accepts only the canonical key plan for that exact signed frame.

  • A critical burn runs if the model decides to.

    P40 actions need an operator AUTH frame bound to the command sequence.

  • State can change between looking and acting.

    A changed AGC revision invalidates the inspection and refuses execution.

  • The agent can shell out around its tools.

    A PreToolUse hook blocks shell tools while Flight Watch is live.

LIVE-RUN FINDINGS

The test suite passed. Reality still found three bugs.

Each failure stopped closed. Fixes widened timing windows or improved the clock; none removed a state, key or authorization check.

Read the Kiro build journal

  1. 01

    INSPECTION_STALE

    Every plan expired before planning

    Agent tool calls were 5–30 s apart; the inspection window was 5 s. It is now 20 s while the exact AGC revision check remains.

  2. 02

    KEY_CADENCE

    Key 2 of 29 was rejected

    A Windows clock made a 100 ms sleep return after 93 ms. The production clock now uses a high-resolution deadline loop.

  3. 03

    AUTH_EXPIRED

    A human could not authorize in time

    Thirty seconds could not fit a human plus several agent calls. The hold is now 120 s; sequence binding and single use remain.

06 / FLIGHT NOTES

Questions before launch.

The short answers reviewers need, including the limits that the demo does not hide.

Is the whole system offline?
No. The daemon, MCP server and emulator use only local listeners, but the Kiro agent itself uses a cloud model.
Does it run Apollo flight software?
No. It is an AGC-faithful subset: 15-bit ones’ complement words, a DSKY state machine, P00, simplified P40, and V25/V34/V37.
Does the acoustic link work over the air?
Not yet. The same-laptop speaker-to-microphone trial detected 0 of 20 frames, and the phone trial has not run. WAV and loopback input work through the same daemon pipeline. See docs/metrics.json.
What does the authentication protect?
HMAC and sequence checks reject forged and replayed frames in tests. They do not stop eavesdropping or jamming, and the public demo keys are not secrets.
How can judges run it without audio hardware?
Use the committed sample WAV, open the local mission console, connect Kiro to the MCP server, and start Flight Watch.
