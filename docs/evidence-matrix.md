# Apollo-26 Evidence & Traceability Matrix

This document keeps requirements from going missing and claims from going unsupported. Update it after every milestone.

## Status
- `PLANNED`: not implemented yet.
- `IMPLEMENTED`: code exists, not fully verified.
- `MEASURED`: the value comes from a stored measurement.
- `VERIFIED`: an acceptance test or property passes and the evidence is stored.
- `FAILED`: real evidence misses the target; show it as it is.

The UI and competition material **may present a number as fact only** when its status is `MEASURED` or `VERIFIED`. Otherwise label it `TARGET` or `UNMEASURED`.

## Change rule
When a requirement changes:
1. Update the PRD/feature requirement.
2. Update the related design and tasks.
3. Update this matrix row.
4. Update schemas/vectors if the contract changes.
5. Re-run the affected verification.
6. Do not keep old evidence for a new version of the behavior.
